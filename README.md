# RPG-Tools by Hibear 4.0 для Foundry VTT v14 (D&D 5e)

Это ветка **для Foundry v14** (D&D 5e 5.3 и 6.x). Для Foundry v13 — версии 3.x.

### Что изменено под v14
- **Авто-бой:** в v14 шаблоны областей стали Регионами. Цели AoE-спасбросков берутся из региона заклинания (dnd5e 6.x) или из шаблона (dnd5e 5.3), с учётом высоты токена.
- **Авто-бой:** dnd5e 6.x хранит данные броска в типе сообщения и `message.system` (активность, цели, исходная карточка) — читаются оба формата, урон привязывается к исходной карточке правильно.
- **Режим броска:** в v14 он называется «режим видимости сообщения» (`core.messageMode`) — спасброски бросаются с ним.
- **Реакции:** бонус к КД (Щит) создаётся в формате эффектов v14 (`system.changes`, `type: "add"`); снимается в начале вашего хода, вне боя — через 6 секунд. Типы лечения берутся из настроек системы.
- **Сундуки и кучи лута:** в v14 у тайлов появился якорь (Anchor X/Y), и точка тайла больше не обязательно левый верхний угол. Попадание кликом, дистанция и бросок предмета на кучу считаются по настоящим границам тайла; новые сундуки и кучи создаются с якорем в углу.
- **Взлом:** расстояние до сундука — по настоящим границам тайла.

Автор: Hibear.

Один модуль, в котором собраны все функции. Мастер включает и выключает их переключателями, в любом сочетании, и они не мешают друг другу.

## Установка
С версии 3.8 папка и id модуля — `rpg-tools-by-hibear` (раньше `rpg-suite`). В Foundry имя папки обязано совпадать с id модуля, а id не может содержать пробелов и заглавных букв, поэтому `RPG Tools by Hibear` записывается как `rpg-tools-by-hibear`.

1. Распакуйте архив в `Data/modules/`. Должно получиться `Data/modules/rpg-tools-by-hibear/module.json`.
2. **Если стояла прежняя версия (папка `rpg-suite`)**: в «Управлении модулями» включите новую **RPG-Tools by Hibear**, а старую отключите. При первом входе мастера все настройки мира, переключатели функций, флаги (портреты, избранное, панель мастера, сундуки, факелы, замки, заметки…) и карточки в чате переносятся под новый id сами; клиентские настройки — у каждого игрока при входе. Пути к файлам `modules/rpg-suite/...` в настройках заменяются на новые. После этого старую папку можно удалить. Пока старая версия включена, новая не запускает функции и показывает предупреждение.
3. В **Управлении модулями** **отключите старые отдельные модули** из таблицы выше.
   Пока старый модуль включён, его функция не запускается (чтобы не было двух копий), а в центре управления горит предупреждение.
4. Настройки старых модулей, цвета кубиков, настройки реакций у предметов и т.п. переносятся сами при первом запуске мастером. Старые данные не удаляются.

### Обновление через GitHub
В репозитории есть `.github/workflows/release.yml`. Опубликуйте релиз с тегом вида `v3.7.0` — GitHub сам впишет версию и ссылки `manifest`/`download` в `module.json`, соберёт `module.zip` и прикрепит к релизу.
Ссылка для установки в Foundry («Установить модуль» → «URL манифеста»): `https://github.com/<владелец>/<репозиторий>/releases/latest/download/module.json`. Дальше Foundry обновляет модуль сам.
Для этой ветки (v14) заведите **отдельный репозиторий** `rpg-tools-by-hibear-v14` с тем же сценарием: id модуля тот же, а ссылка-манифест у v13 и v14 своя. Назовите репозиторий v13 `rpg-tools-by-hibear` — так проще ориентироваться (имя репозитория на работу не влияет). `.gitignore` не пускает в репозиторий `config.json` бота (там токен Discord) и `node_modules`.

### Discord-бот и обновления
Модуль не обращается к папке бота — браузер мастера подключается к уже запущенному боту по `ws://127.0.0.1:30500`, поэтому путь к боту указывать не нужно.
При первом запуске `start-windows.bat` / `start-macos.command` из папки модуля бот переносится в постоянную папку
(Windows: `%LOCALAPPDATA%\RPG-Tools\discord-bot`, macOS: `~/Library/Application Support/RPG-Tools/discord-bot`), переносит туда старый `config.json`
и делает ярлык «RPG-Tools Discord-бот» на рабочем столе. Токен и зависимости живут там, и Foundry их не трогает, когда обновляет модуль.
При каждом запуске ярлыком `launcher.mjs` сверяет код с папкой модуля и, если модуль обновился, забирает новую версию бота (`config.json` не трогает), а зависимости переставляет только при смене `package.json`, системы или версии Node.
Бот при подключении сообщает свою версию и версию протокола: старый бот продолжает работать, а Foundry подскажет его перезапустить.

## Центр управления
Открыть можно четырьмя способами:
- кнопка **ползунков** на левой панели инструментов (раздел «Токены»);
- кнопка **«Открыть центр управления»** вверху вкладки «Настройки» в сайдбаре;
- **Shift+M** (меняется в «Управлении клавишами»);
- **Настройки → Настройки модулей → RPG-Tools by Hibear → «Открыть центр управления»**.

Слева — список функций с переключателями, справа — описание выбранной функции, что она умеет, и все её настройки.
У каждой функции есть кнопка **«?» — «Как это работает?»**: полная инструкция, что умеет функция и как ею пользоваться.
У голосовых портретов есть ещё кнопка **«Как запустить Discord-бота»**. Тексты инструкций лежат в `core/help.js`.
- **Мастер** включает и выключает функции и меняет настройки мира. После сохранения у всех игроков страница перезагрузится, а выключенные функции не загружаются совсем: ни хуков, ни кнопок, ни настроек.
- **Игрок** видит описания и может менять свои личные настройки (масштаб UI-интерфейса, громкость, цвет кубиков и т.д.).

Описания функций лежат в `lang/ru.json` → `RPGSUITE.Features.<id>` (`title`, `description`, `details` — по строке на пункт). Их можно править как угодно.

## Как функции работают вместе
- **Реакции + Авто-бой.** После попадания Авто-бой ждёт, пока цель решит, использовать ли Щит. Потом КД проверяется заново: если атака теперь промахивается, урон не бросается и не списывается. Отражение снарядов и Невероятное уклонение уменьшают урон, который списывает Авто-бой. Способность, применённая как реакция (например, Контрзаклинание со спасброском), не создаёт карточку спасбросков.
- **Реакции + UI-интерфейс.** Использованная реакция сама отмечается ромбиком на панели.
- **Эпические запросы бросков + 3D-кубики.** Кубики видны поверх затемнения, а результат на карточке открывается, когда они остановились.
- **Взлом замков + Сундуки.** Клавиша «Взломать ближайший замок» находит и двери, и запертые сундуки. Сундуки открывают своё окно вскрытия и понимают отмычки и воровские инструменты, названные в настройках «Взлома».
- **Сундуки + панели.** Ячейки «Панели мастера» и UI-интерфейса, утащенные на карту, не превращаются в кучи лута.
- **Предупреждения.** Авто-бой вместе с Midi-QOL спишет урон дважды, 3D-кубики вместе с Dice So Nice покажут кости дважды — центр управления и уведомление при запуске об этом скажут.

## Макросы (новые адреса API)
```js
game.rpgSuite.openManager("dice");                 // открыть центр управления на нужной функции
game.rpgSuite.api.rolls.request({ tokens: canvas.tokens.controlled, type: "skill", skill: "ath", dc: 15, reason: "Выбить дверь" });
// вместо tokens можно actors: ["Кайзер"] или users: ["Аня"] (берётся их персонаж)
game.rpgSuite.api.rolls.openPanel();
game.rpgSuite.api.loot.openReward();
game.rpgSuite.api.reactions.configureItem(actor.items.getName("Парирование"));
game.rpgSuite.api.dice.show("2d20 + 1d6");
game.rpgSuite.api.gmbar.toggle();                 // показать / скрыть панель мастера (или Shift+G)
game.rpgSuite.openHelp("piles");                   // окно «Как это работает?» любой функции ("discord" — инструкция по боту)
RPGCalendar.advance("hour");                       // календарь (то же: game.rpgSuite.api.calendar)
game.rpgSuite.api.light.light(token.document, "torch");
game.rpgSuite.api.lockpick.lockpickNearest();
game.rpgSuite.api.initiative.gather();             // окно «Собрать бой»
game.rpgSuite.api.piles.openMerchant(actor);       // и по-старому game.pilesTool
game.rpgSuite.api.whisper.open();
game.rpgSuite.api.notebook.toggle();
game.rpgSuite.api.mannequin.toggle();
game.voicePortraits.setEmotion(game.user, "happy");
game.rpgSuite.isActive("combat");                  // запущена ли функция
```
Старые адреса вида `game.modules.get("bg3-roll-requests").api` больше не работают — поменяйте в макросах на новые.

## Для разработки: как устроено и как добавить функцию
```
core/main.js           — реестр функций (FEATURES), запуск, кнопки открытия
core/manager.js        — окно «Центр управления»
core/feature-hooks.js  — отложенные хуки: подписки функции включаются только если она включена
core/shared.js         — шина для связи функций без прямых импортов друг друга
core/socket.js         — общий сокет, сообщения маршрутизируются по id функции
core/migrate.js        — перенос данных старых модулей
features/<функция>/    — код и стили каждой функции
```
1. Создайте `features/<имя>/index.js`. В начале: `const Hooks = createFeatureHooks();`, дальше пишите `Hooks.on(...)` / `Hooks.once("init", ...)` как в обычном модуле, и экспортируйте `export function setup() { Hooks.activate(); }`.
2. Добавьте запись в `FEATURES` в `core/main.js`: `id`, `icon`, `settingPrefix`, по желанию `legacyModule`, `conflicts`, `system`, `api`.
3. Добавьте `title`, `description`, `details` в `lang/*.json` → `RPGSUITE.Features.<id>`.
4. Правила, чтобы функции не конфликтовали:
   - настройки — `game.settings.register(SUITE_ID, "<приставка>-<ключ>")` (`SUITE_ID` = `"rpg-tools-by-hibear"` из `core/constants.js`) (по приставке центр управления сам покажет их в окне функции);
   - флаги — `doc.setFlag(SUITE_ID, "<приставка>.<ключ>")`;
   - сокет — `suiteSocket.emit("<id функции>", data)` / `.on(...)`;
   - связь с другой функцией — `game.rpgSuite.isActive("<id>")`, `shared.track/wait` или свой хук `rpgSuite.*`, без импорта чужого кода;
   - CSS — свои id и классы; глобальные правки только через класс на `<body>`, который функция ставит сама.
5. Стили функции допишите в `styles` в `module.json`.
